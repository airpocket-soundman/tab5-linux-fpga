01

開発目的

01

Linux採用の目的

M5Stack Tab5のESP32-P4上でNOMMU Linuxを動かし、LinuxのAPIと既存の開発資産を利用します。MeOSとの速度比較は未実施です。

02

FPGA側メモリの利用方式

Tang Primer 20K側の128MB DDR3を、READ / WRITEなどで操作する外部データ領域として利用する構想です。Linuxの空きRAMが128MB増える仕組みではありません。

03

段階的な検証方針

1コア構成を起点に、上流修正、低速通信、ドライバとDMA、研究アプリとの接続を順に検証します。

02

システム構成

Tab5でOSとアプリケーションを実行し、通信ドライバを介してFPGA側のデータ領域と演算回路を利用する構成を検討しています。

FPGA側DDR3の位置付け

アプリが転送を要求し、FPGA側でデータを読み書きします。Linuxの通常RAMが透過的に増える構成ではありません。

05

開発計画と完了条件

現在はL0が進行中。日付による期限は未設定です。各段階の完了条件を満たしてから次へ進みます。

  1. L0
    進行中

    1コア起動の基準を作る

    ビルド環境・依存バージョン・イメージハッシュ・起動ログを保存し、シェル、対応液晶、Keyboard、Wi-Fi、SSH、メモリ情報を確認する。

  2. L1
    未完了

    上流修正を評価する

    修正の採否と依存関係を記録し、L0の機能を再確認する。SMP有効化は安定性の検証後に判断する。

  3. L2
    未着手

    FPGAと最小通信する

    キャリア仕様との照合、GPIO競合とPARLIO対応の確認を経て、低速コマンド送受信とデータ照合を実機で完了する。

  4. L3
    未着手

    ドライバとDMAを実装する

    /dev/からREAD / WRITEを実行し、タイムアウト、エラー通知、バッファ寿命、キャッシュ同期を検証する。

  5. L4
    未着手

    外部メモリ研究につなぐ

    研究アプリからDDR3の128MB全域を分割して読み書き・照合し、帯域、遅延、CPU負荷を記録する。

カーネル更新、SMP、FPGAドライバ追加を同時に行わず、1コア構成との差を変更ごとに確認します。ST7121の表示対応はL0の前提を整える実験です。

06

次の作業

  1. 単体表示テストを基準に、ST7121初期化表とタイミングをLinuxへ移植した成果物を実機で検証する。調査はユーザーの再開指示を受けて進める。
  2. USB付近の発熱について、温度と発生条件を記録して原因を調べる。現在は温度未測定で、正常性も未判定。
  3. Linuxへ戻した後、Wi-Fiクライアント接続・SSH・Keyboard・設定永続化を確認してL0の証跡をそろえる。
  4. 上流との差分を整理し、割り込み・障害処理などの修正を段階的に評価する。
  5. キャリア共通仕様を照合し、PARLIOのレジスタ・ピン制御・DMA・Linux対応を調査して最小通信を設計する。
